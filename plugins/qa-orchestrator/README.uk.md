# qa-orchestrator

QA однієї або кількох Jira-задач через агентів. Оркестратор читає задачу, один раз питає, який скіл запускати, ставить
лейбл, роздає кожен крок свіжому субагенту, показує чернетку коментаря в Jira і постить її тільки після вашого "так".
Ставить `jira-qa`, `qa-pipeline` і `qa-design-check` як залежності.

## Що потрібно

- Claude Code;
- `node` (він і так потрібен для `playwright-cli`);
- `playwright-cli` для браузера;
- Atlassian (Jira) MCP сервер;
- опційно, щоб читати код з MR у `qa-pipeline`: `glab`, залогінений токеном з доступом до репозиторію продукту;
- опційно, для `qa-design-check`: Figma MCP або персональний токен Figma.

## Встановлення

```bash
claude plugin marketplace add stokrattt/stokratt-plugins
claude plugin install qa-orchestrator@stokratt-plugins
```

## Як запустити

У Claude Code: "run QA on PROJ-123" або "use qa-orchestrator for PROJ-123".

Оркестратор працює як субагент і не може сам показати вибір. Він повертає блок `QUESTIONS` з JSON, основна сесія
показує його як звичайне питання з кнопками і передає відповідь назад тому самому оркестратору.

Коментар у Jira пишеться мовою задачі.

## Що всередині

| Що                     | Навіщо                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------- |
| `qa-orchestrator`      | читає задачу, питає скіл, платформи, URL, ставить лейбл, роздає роботу, показує чернетку і постить її   |
| `qa-skill-runner`      | виконує рівно один скіл або один крок `qa-pipeline` у чистому контексті, повертає чернетку              |
| `qa-artifact-reviewer` | гейт між кроками `qa-pipeline`: PASS або список дір                                                     |

Хуки:

- `label-first-gate`: раннер не стартує, поки на задачі нема QA-лейбла;
- `qa-jira-write-gate`: раннер і рев'юер не пишуть у Jira;
- `qa-draft-gate`: QA-коментар, футер `ai-qa-meta` якого не збігається з текстом, не постується;
- `blocked-claim-gate`: раннер не закінчує хід фразою "браузер недоступний" без рядка `attempt:`;
- `orchestrator-stop-gate`: оркестратор не зупиняється посеред маршруту без питання чи підсумку.

## Налаштування

QA-лейбл за замовчуванням `ai-qa-tested`. Щоб взяти інший, задайте змінну середовища `AI_QA_LABEL` (наприклад, у блоці
`env` файлу `.claude/settings.json`) і назвіть той самий лейбл у `CLAUDE.md` проєкту, щоб оркестратор ставив те, що
перевіряє хук.

Якщо проєкт має власні копії цих агентів у `.claude/agents/`, Claude Code бере їх. Інакше агенти мають префікс
`qa-orchestrator:`, і оркестратор це знає.
