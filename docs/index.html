Inside a qa-pipeline run

Who does what, from your sentence to the posted comment.

Youqa-orchestratorAgentsJira
  1. You"run QA on PROJ-123"You name the ticket. That is the whole request.
  2. request
    qa-orchestratorReads the ticketAcceptance criteria, comments, Figma links, the Environment field.
  3. questions
    YouYou answer onceSkill, platforms, design check, the URL. For the pipeline also coverage and whether to read the MR code. The only stop until the draft.
  4. answers
    qa-orchestratorLabels first, then hands out workEvery step goes to a fresh agent. It holds only their verdicts.
  5. label
    JiraLabel ai-qa-testedWritten before any agent starts.hook: label-first-gate
  6. step N
    qa-skill-runnerRunner writes one file per step
    1. context.md, everything from the ticket
    2. requirements.md, numbered and groomed
    3. checklist.md, one pass or fail per item
    4. test-cases.md, steps and expected results
    script: check-pipeline-coverage.mjs
  7. qa-artifact-reviewerReviewer gates every filePASS, or a numbered list the runner fixes. Two tries, then the run stops and shows you the list.

    repeats for steps 1 to 4

  8. step 5
    qa-skill-runnerStep 5 runs the casesSmoke case first: a broken core stops the run, a wrong value is a bug. Then desktop, mobile and tablet in a real browser.hook: blocked-claim-gate
  9. auditorEvidence auditEvery passed line needs proof in the run log, or it turns into "not proven".
  10. draft
    qa-orchestratorChecks for duplicate bugsOne Jira search per bug before you see it.
  11. draft and bugs
    YouYou approveThe comment as written, each bug, one question block: file this bug, post the comment?
  12. yes
    qa-orchestratorFiles the bugs, then postsBug keys go into the comment lines they belong to.
  13. post
    JiraComment and bugs on the ticketThe status of the ticket is never changed.hooks: qa-jira-write-gate, qa-draft-gate

Rules held by code

Hooks stop the agents before a rule breaks.

label-first-gate
No runner starts before the ticket has the QA label.
qa-jira-write-gate
Runners and reviewers never write to Jira.
qa-draft-gate
A comment that contradicts its own footer is not posted.
qa-skill-gate
QA skills run only inside the runner.
